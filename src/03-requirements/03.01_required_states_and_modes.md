# Required states and modes

The ChatCard System shall operate in distinct states and modes that determine available functionality, security posture, and user interaction capabilities. This section defines the required operational states and modes, their characteristics, and transition requirements.

## State and Mode Overview

The system employs both **states** (conditions that affect all operations) and **modes** (distinct operational contexts with different requirement sets). A state transition diagram is provided in Appendix A.

## 3.1.1 Power States

The system shall support the following power states:

### STATE-PWR-001: Off/Unpowered State

**Definition**: The device has no power and is completely inactive.

**Characteristics**:

- No functionality available
- All volatile memory cleared
- Bluetooth radio inactive
- Display inactive
- Current consumption: 0 μA (excluding battery self-discharge)

**Entry conditions**:

- User performs power-off sequence
- Battery completely depleted
- Device not connected to power source

**Exit conditions**:

- User performs power-on sequence
- Battery inserted or charged above minimum threshold

### STATE-PWR-002: Sleep/Standby State

**Definition**: Low-power state maintaining essential functionality for quick wake.

**Characteristics**:

- Bluetooth LE connection maintained (if previously connected)
- Can wake on Bluetooth activity or user input
- Display inactive
- Encryption keys retained in secure storage
- Maximum current consumption: 50 μA average

**Entry conditions**:

- No user activity for configured timeout (default: 30 seconds)
- User explicitly activates sleep mode
- While in Active state

**Exit conditions**:

- User input detected (button press)
- Incoming message received via Bluetooth
- Bluetooth connection event

**Timing requirement**: Transition from Sleep to Active shall complete within 100 milliseconds.

### STATE-PWR-003: Active/Ready State

**Definition**: Fully operational state with all subsystems powered.

**Characteristics**:

- Display active
- Bluetooth LE active
- All cryptographic functions available
- User input processing enabled
- Full messaging capability available
- Maximum current consumption: 15 mA average

**Entry conditions**:

- System boot complete from Off state
- Wake from Sleep state
- User activity detected

**Exit conditions**:

- Sleep timeout expires without user activity
- User initiates power-off sequence
- Critical battery level reached

## 3.1.2 Pairing States

The system shall support the following Bluetooth pairing states:

### STATE-PAIR-001: Unpaired State

**Definition**: No active Bluetooth pairing with a mobile device.

**Characteristics**:

- Cannot send or receive messages
- Composed messages queued locally (encrypted)
- Pairing mode can be initiated
- Security operations limited to local device only

**Entry conditions**:

- First power-on (factory state)
- User explicitly removes pairing
- Pairing failure or timeout
- Security violation detected requiring re-pairing

**Exit conditions**:

- Successful pairing completed
- Transition to Paired state

### STATE-PAIR-002: Pairing Mode

**Definition**: Actively advertising and accepting pairing requests.

**Characteristics**:

- Bluetooth LE advertising active
- Display shows pairing code or status
- User confirmation required for pairing completion
- Timeout after 2 minutes if pairing not completed
- Elevated power consumption

**Entry conditions**:

- User initiates pairing sequence from Unpaired state
- User initiates re-pairing from Paired state

**Exit conditions**:

- Pairing successfully completed
- Pairing timeout (2 minutes)
- User cancels pairing
- Security violation detected

**Security requirement**: Pairing shall use Bluetooth LE Secure Connections with numeric comparison (see REQ-SEC-002).

### STATE-PAIR-003: Paired State

**Definition**: Active pairing established with a mobile device.

**Characteristics**:

- Bluetooth bonding information stored
- Can establish connections to paired device
- Full messaging capability available
- May be connected or disconnected

**Entry conditions**:

- Successful completion of pairing process
- Pairing information restored from secure storage

**Exit conditions**:

- User explicitly removes pairing
- Security violation detected
- Maximum failed connection attempts exceeded (10 attempts)

## 3.1.3 Connection States

The system shall support the following connection states (substates of Paired):

### STATE-CONN-001: Disconnected State

**Definition**: Paired but no active Bluetooth connection.

**Characteristics**:

- Messages queued locally in encrypted storage
- Periodic connection attempts to paired device
- User notified of disconnected status
- Display shows disconnection indicator

**Entry conditions**:

- Bluetooth connection lost
- Device moves out of range
- Phone Bluetooth disabled
- Connection terminated by either device

**Exit conditions**:

- Successful connection established
- Transition to Connected state

**Retry requirement**: System shall attempt reconnection every 30 seconds when in Disconnected state while in Active power state.

### STATE-CONN-002: Connected State

**Definition**: Active Bluetooth LE connection established.

**Characteristics**:

- Messages transmitted immediately upon sending
- Can receive messages in real-time
- Connection quality monitored
- Display shows connection indicator
- Encrypted session keys active

**Entry conditions**:

- Successful Bluetooth LE connection establishment
- Authentication with paired device completed

**Exit conditions**:

- Connection loss detected (timeout or disconnect event)
- User power-off sequence
- Transition to Sleep state (connection may be maintained)

**Connection monitoring**: System shall detect connection loss within 5 seconds and transition to Disconnected state.

## 3.1.4 Security States

The system shall support the following security states:

### STATE-SEC-001: Locked State

**Definition**: Device secured, no plaintext visible or accessible.

**Characteristics**:

- Display blanked or shows lock indicator only
- User input disabled except for unlock sequence
- Messages received but not displayed
- No composition of new messages allowed
- Encryption keys remain in secure storage

**Entry conditions**:

- User explicitly locks device
- Automatic lock timeout expires (configurable, default: 1 minute)
- Device detects tamper condition

**Exit conditions**:

- User provides correct unlock credential
- Transition to Unlocked state

**Security requirement**: Lock state shall prevent access to all message plaintext (see REQ-SEC-007).

### STATE-SEC-002: Unlocked/Authenticated State

**Definition**: User authenticated, full access to device functionality.

**Characteristics**:

- Messages can be read and composed
- All user interface functions available
- Encryption keys accessible for cryptographic operations
- Auto-lock timer active

**Entry conditions**:

- Successful authentication (PIN, pattern, or biometric if supported)
- Device boot with auto-unlock enabled (if configured)

**Exit conditions**:

- User locks device
- Auto-lock timeout expires
- Tamper detection triggered

**Auto-lock requirement**: System shall automatically transition to Locked state after configured timeout (default 1 minute, configurable 15 seconds to 5 minutes).

## 3.1.5 Key Management States

The system shall support the following cryptographic key states:

### STATE-KEY-001: Key Initialization Required

**Definition**: No encryption keys established with communication partners.

**Characteristics**:

- Cannot send or receive encrypted messages
- Key generation and exchange must be completed
- Local device keys may or may not exist
- User notified that setup is required

**Entry conditions**:

- First device initialization
- User initiates key reset
- Key compromise detected

**Exit conditions**:

- Successful key generation and exchange
- Transition to Keys Established state

### STATE-KEY-002: Keys Established

**Definition**: Valid encryption keys available for secure messaging.

**Characteristics**:

- Normal encrypted messaging operations available
- Keys stored in secure storage
- Key rotation monitoring active
- Forward secrecy maintained

**Entry conditions**:

- Successful key generation and exchange
- Key restoration from secure backup

**Exit conditions**:

- Key expiration or rotation required
- Key compromise detected
- User initiates key reset

**Key lifetime**: System shall support key rotation as specified in REQ-SEC-002. Keys shall be rotated automatically based on time or message count thresholds.

### STATE-KEY-003: Key Rotation Pending

**Definition**: Current keys still valid but rotation recommended or required.

**Characteristics**:

- Existing keys remain operational
- User notified of rotation recommendation
- Automatic rotation attempted during next connection
- Messages continue to flow using current keys

**Entry conditions**:

- Key age exceeds rotation threshold
- Message count exceeds rotation threshold
- Manual rotation initiated

**Exit conditions**:

- Successful key rotation completed
- Return to Keys Established state
- Key rotation timeout (forced rotation required)

**Rotation timing**: System shall complete key rotation within 60 seconds of connection establishment when in Key Rotation Pending state.

## 3.1.6 Operational Modes

The system shall support the following operational modes:

### MODE-001: Setup/Provisioning Mode

**Definition**: Initial device configuration and security establishment.

**Characteristics**:

- Guided setup process active
- Device pairing enabled
- Initial key generation
- User preferences configuration
- Extended timeout periods
- Detailed status messages

**Entry conditions**:

- First power-on (factory state)
- User initiates factory reset
- Critical configuration missing

**Exit conditions**:

- All required setup steps completed:
  - Device pairing established
  - Encryption keys generated
  - User authentication configured
  - Transition to Normal Operation Mode

**Setup requirements**:

- User shall configure unlock method (PIN minimum 6 digits or pattern)
- System shall generate and exchange encryption keys
- System shall verify Bluetooth pairing
- Process shall be completable within 5 minutes

### MODE-002: Normal Operation Mode

**Definition**: Standard messaging functionality for daily use.

**Characteristics**:

- Full messaging capabilities available
- Standard user interface active
- Normal timeout periods
- Automatic state transitions enabled
- Background key rotation as needed

**Entry conditions**:

- Setup/Provisioning mode completed successfully
- Recovery from Degraded or Maintenance modes

**Exit conditions**:

- User initiates setup/reset
- System enters Maintenance mode
- Degraded operation detected

**Normal operation requirements**:

- All states defined in sections 3.1.1-3.1.5 shall be operational
- State transitions shall occur as specified
- Performance shall meet timing requirements throughout

### MODE-003: Degraded Operation Mode

**Definition**: Limited functionality due to connection issues or resource constraints.

**Characteristics**:

- Message composition allowed
- Messages queued locally (cannot transmit)
- Receive functionality disabled or delayed
- User notified of degraded state
- Automatic recovery attempts ongoing

**Entry conditions**:

- Bluetooth connection unavailable for extended period (>5 minutes)
- Paired device not responding
- Low battery condition (<10% remaining)

**Exit conditions**:

- Connection restored
- Battery charged above threshold
- Return to Normal Operation Mode

**Degraded operation requirements**:

- System shall queue up to 100 outbound messages
- Queued messages shall be encrypted and stored securely
- User shall be able to compose messages normally
- System shall automatically recover when conditions improve

### MODE-004: Maintenance/Update Mode

**Definition**: Firmware update and diagnostic operations.

**Characteristics**:

- Normal messaging disabled
- Firmware update process active
- Diagnostic functions available
- Secure boot verification active
- Extended power-on period

**Entry conditions**:

- User initiates firmware update
- Authorized diagnostic connection established
- Critical security update required

**Exit conditions**:

- Firmware update completed successfully
- Diagnostic session terminated
- Update failure (rollback to previous firmware)
- Return to Normal Operation Mode or Setup Mode

**Security requirements for Maintenance Mode**:

- Firmware updates shall be cryptographically signed (see REQ-SEC-001)
- Update process shall verify signature before installation
- Rollback capability shall be maintained
- Message keys shall not be accessible during maintenance
- Update process shall complete or timeout within 10 minutes

## 3.1.8 State Transition Requirements

**TRANS-001**: All state transitions shall complete within specified timing requirements or revert to previous stable state.

**TRANS-002**: State transitions that fail security checks shall immediately transition to Locked state and log the security event.

**TRANS-003**: Power state transitions shall preserve encryption keys in secure storage across power cycles.

**TRANS-004**: The system shall maintain a persistent record of current state to enable proper recovery after unexpected power loss.

**TRANS-005**: State transitions shall be atomic - no intermediate state shall be visible to the user or compromise security.
