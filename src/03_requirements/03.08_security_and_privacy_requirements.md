# Security and privacy requirements

## Security Standards Compliance

The ChatCard System shall be designed and evaluated in accordance with applicable Common Criteria Protection Profiles as referenced in Section 2. The system shall meet security requirements derived from the following Protection Profiles:

### Cryptographic Requirements

**REQ-SEC-001**: The system shall implement cryptographic functions in accordance with the Cryptographic Service Provider Protection Profile, including:

- Generation and secure storage of cryptographic keys
- End-to-end encryption of all message content
- Resistance to attacks with moderate attack potential
- Protection of private signing keys from unauthorized access

**REQ-SEC-002**: Bluetooth key generation shall comply with PP-Module for Bluetooth requirements (FCS_CKM_EXT.8), including:

- Generation of key pairs for Bluetooth LE pairing
- Secure key exchange protocols
- Time-limited or event-triggered key regeneration

### Communication Security Requirements

**REQ-SEC-003**: The system shall implement secure communications in accordance with the IoT Secure Communications Module Protection Profile, including:

- Guaranteed confidentiality of all transmitted messages
- Integrity protection to detect message tampering
- Authentication of communicating devices
- Protection against replay attacks

**REQ-SEC-004**: All communications between the ChatCard device and mobile phone shall be protected through:

- Encrypted Bluetooth LE channels
- Mutual authentication of paired devices
- Session key management and rotation

### Device Security Requirements

**REQ-SEC-005**: If a secure element is implemented, it shall comply with the IoT Secure Element Protection Profile (IoT-SE-PP) requirements for:

- Isolated execution environment for cryptographic operations
- Tamper-resistant key storage
- Secure boot and firmware verification

### Security Environment

**REQ-SEC-006**: The system shall operate securely in environments where:

- The mobile phone may be compromised or untrusted
- The public internet transport is assumed hostile
- Physical access to the device may occur
- Bluetooth LE communication may be subject to interception attempts

### Privacy Requirements

**REQ-SEC-007**: The system shall protect user privacy by:

- Not storing message plaintext outside the secure device
- Minimizing metadata exposure during message transport
- Providing user control over message retention and deletion
- Avoiding correlation of messages to user identity where possible

### Security Certification

**REQ-SEC-008**: The system design shall support evaluation against Common Criteria Protection Profiles to enable potential security certification at an appropriate Evaluation Assurance Level (EAL).
