# Pairing States

The system shall support the following Bluetooth pairing states:

## STATE-PAIR-001: Unpaired State

**Definition**: No active Bluetooth pairing with a mobile device.

**Characteristics**:

- Cannot send or receive messages
- Composed messages queued locally (encrypted)
- Pairing mode can be initiated
- Security operations limited to local device only

**Entry conditions**:

- First power-on (factory state)
- User explicitly removes pairing
- Pairing failure or timeout
- Security violation detected requiring re-pairing

**Exit conditions**:

- Successful pairing completed
- Transition to Paired state

## STATE-PAIR-002: Pairing Mode

**Definition**: Actively advertising and accepting pairing requests.

**Characteristics**:

- Bluetooth LE advertising active
- Display shows pairing code or status
- User confirmation required for pairing completion
- Timeout after 2 minutes if pairing not completed
- Elevated power consumption

**Entry conditions**:

- User initiates pairing sequence from Unpaired state
- User initiates re-pairing from Paired state

**Exit conditions**:

- Pairing successfully completed
- Pairing timeout (2 minutes)
- User cancels pairing
- Security violation detected

**Security requirement**: Pairing shall use Bluetooth LE Secure Connections with numeric comparison (see REQ-SEC-002).

## STATE-PAIR-003: Paired State

**Definition**: Active pairing established with a mobile device.

**Characteristics**:

- Bluetooth bonding information stored
- Can establish connections to paired device
- Full messaging capability available
- May be connected or disconnected

**Entry conditions**:

- Successful completion of pairing process
- Pairing information restored from secure storage

**Exit conditions**:

- User explicitly removes pairing
- Security violation detected
- Maximum failed connection attempts exceeded (10 attempts)
