# Key Management States

The system shall support the following cryptographic key states:

## STATE-KEY-001: Key Initialization Required

**Definition**: No encryption keys established with communication partners.

**Characteristics**:

- Cannot send or receive encrypted messages
- Key generation and exchange must be completed
- Local device keys may or may not exist
- User notified that setup is required

**Entry conditions**:

- First device initialization
- User initiates key reset
- Key compromise detected

**Exit conditions**:

- Successful key generation and exchange
- Transition to Keys Established state

## STATE-KEY-002: Keys Established

**Definition**: Valid encryption keys available for secure messaging.

**Characteristics**:

- Normal encrypted messaging operations available
- Keys stored in secure storage
- Key rotation monitoring active
- Forward secrecy maintained

**Entry conditions**:

- Successful key generation and exchange
- Key restoration from secure backup

**Exit conditions**:

- Key expiration or rotation required
- Key compromise detected
- User initiates key reset

**Key lifetime**: System shall support key rotation as specified in REQ-SEC-002. Keys shall be rotated automatically based on time or message count thresholds.

## STATE-KEY-003: Key Rotation Pending

**Definition**: Current keys still valid but rotation recommended or required.

**Characteristics**:

- Existing keys remain operational
- User notified of rotation recommendation
- Automatic rotation attempted during next connection
- Messages continue to flow using current keys

**Entry conditions**:

- Key age exceeds rotation threshold
- Message count exceeds rotation threshold
- Manual rotation initiated

**Exit conditions**:

- Successful key rotation completed
- Return to Keys Established state
- Key rotation timeout (forced rotation required)

**Rotation timing**: System shall complete key rotation within 60 seconds of connection establishment when in Key Rotation Pending state.
